## 3. HỢP ĐỒNG CÔNG KHAI (PUBLIC CONTRACTS)

### A. Dummy Engine Interface & Functions (`@engines/dummy/engine`)

```typescript
export type DummyPlayer = 'player1' | 'player2';

export interface DummyMove {
  readonly player: DummyPlayer;
  readonly points: number;
}

export interface DummyState {
  readonly turn: number;
  readonly maxTurns: number;
  readonly currentPlayer: DummyPlayer;
  readonly scores: { readonly player1: number; readonly player2: number };
  readonly isTerminal: boolean;
  readonly winner: DummyPlayer | 'draw' | null;
  readonly moveHistory: readonly DummyMove[];
}

export function createDummyInitialState(maxTurns?: number): DummyState;
export function applyDummyMove(state: DummyState, move: DummyMove): DummyState;
export function isDummyTerminal(state: DummyState): boolean;
export function getDummyWinner(state: DummyState): DummyPlayer | 'draw' | null;
```

_Ví dụ gọi từ Client View / Worker AI / Edge Function:_

```typescript
import { createDummyInitialState, applyDummyMove } from '@engines/dummy/engine';

const s0 = createDummyInitialState(6);
const s1 = applyDummyMove(s0, { player: 'player1', points: 3 });
// s1.turn === 2, s1.currentPlayer === 'player2', s1.scores.player1 === 3
```

## 4. QUYẾT ĐỊNH THIẾT KẾ

| Quyết định                                             | Lý do lựa chọn                                                                                                                                         | Phương án đã loại bỏ & Lý do loại                                                                                        |
| :----------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------- |
| **TypeScript Solution Style References**               | Typecheck toàn bộ 3 phân vùng (`engines`, `src`, `node`) bằng **1 lệnh duy nhất** `tsc -b`, cô lập `lib` riêng từng vùng.                              | _Chạy nhiều lệnh tsc nối đuôi (`tsc -p ... && tsc -p ...`)_: Chậm hơn, dễ bỏ sót thư mục mới khi cấu hình mở rộng.       |
| **`dependency-cruiser` cưỡng chế luật phân tầng**      | Định nghĩa tường minh ma trận cấm import theo thư mục (`from.path` $\rightarrow$ `to.path`) với thông báo lỗi tiếng Việt chỉ rõ nguyên nhân kiến trúc. | _`madge`_: Chỉ phát hiện circular đơn giản, không hỗ trợ khai báo ma trận cấm import đa tầng chi tiết.                   |
| **Dummy Engine độc lập không phụ thuộc interface tạm** | Tạo máy trạng thái tối giản tự định nghĩa để kiểm chứng hạ tầng trước, tránh tạo interface dở dang gây nợ kỹ thuật.                                    | _Viết interface Engine sơ khai ở P0.2_: Dễ gây xáo trộn và xung đột khi thiết kế interface `Engine<S,M>` chuẩn tại P0.6. |

## 7. ĐẦU VÀO GỢI Ý CHO PHASE KẾ TIẾP (P0.3 — CI/CD GitHub Actions & Automation)

Phase **P0.3** cần đưa trọn bộ các câu lệnh kiểm tra chất lượng đã được chuẩn hóa tại P0.1 và P0.2 vào GitHub Actions workflow:

1. **Lệnh Typecheck**: `npm run typecheck` (`tsc -b`).
2. **Lệnh Linting**: `npm run lint` (ESLint 9 Flat Config + boundary guard).
3. **Lệnh Format**: `npm run format:check` (Prettier).
4. **Lệnh Kiến trúc**: `npm run check:deps` (`dependency-cruiser`).
5. **Lệnh Test**: `npm run test` (Vitest node environment).
6. **Lệnh Build**: `npm run build` (Vite production bundle).
7. **Lưu ý Node Version**: Chạy runner trên Node 20 LTS (`20.x`) khớp với `.nvmrc` và `package.json engines`.
