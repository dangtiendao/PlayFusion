## 1. Tóm Tắt (Executive Summary)

Phase P2.1 đã hoàn thành trọn vẹn toàn bộ 3 phần nền tảng cốt lõi của **Nhóm 2 (Backend, Cloud Infrastructure & Authentication)**:

1. **P2.1a — Hạ Tầng, Cấu Hình & Tầng Repositories**:

   - Thiết lập kết nối 2 project Supabase độc lập (`webgamehub-dev` và `webgamehub-prod`) tại Singapore (`ap-southeast-1`).
   - Khởi tạo client singleton `src/repositories/supabaseClient.ts`, kiểm định biến môi trường fail-fast `src/core/env.ts`.
   - Thiết lập hàng rào phụ thuộc `dependency-cruiser` cấm triệt để import Supabase SDK ngoài `src/repositories/` ("Cổng thoát hiểm" backend).
   - Health check kết nối máy chủ không phụ thuộc bảng DB qua GoTrue `/auth/v1/health`.

2. **P2.1b — Luồng Xác Thực (Ẩn Danh + Google OAuth + Nâng Cấp Không Mất ID)**:

   - **Vào là chơi ngay (Khách Ẩn Danh)**: Tự động khởi tạo phiên khách `signInAnonymously()` khi mở app mà không chặn giao diện offline (Offline-First).
   - **Nâng cấp bảo toàn dữ liệu (Zero Data Loss)**: Dùng `linkIdentity` để nâng cấp tài khoản khách lên Google **giữ nguyên `user.id`** $\rightarrow$ toàn bộ lịch sử, thống kê offline/online không bị mất.
   - **Quản lý phiên qua Zustand Store**: `useAuthStore` không persist (để Supabase SDK tự quản lý token), chống double-init trong React StrictMode.

3. **P2.1c — Bảng Profiles, RLS, Profile Repository & Trang Profile Hoàn Chỉnh**:
   - **Bảng `public.profiles`**: Tạo bảng hồ sơ đầu tiên, kích hoạt Row Level Security (RLS) với policy SELECT công khai và policy UPDATE chỉ chính chủ.
   - **Database Triggers (SECURITY DEFINER)**: Tự động tạo hồ sơ mặc định `Khách-xxxxxx` khi có user mới, tự động đồng bộ tên/avatar từ Google khi nâng cấp (bảo vệ không ghi đè tên người dùng đã tự đổi), và Trigger chặn client tự ý sửa đổi `role` / `user_id`.
   - **Tầng `profileRepository.ts`**: Cung cấp `getMyProfile()`, `updateDisplayName()` kèm kiểm định client 2..20 ký tự mirror DB constraint.
   - **Trang `ProfilePage.tsx`**: Hoàn thiện giao diện hồ sơ người dùng (PlayerBadge tối giản, đổi tên, banner nâng cấp Google, bảng thành tích offline từ `gameLocalData`).

## 3. Hợp Đồng Công Khai (Public API Contract)

### A. Database Schema & RLS (`supabase/migrations/0001_profiles.sql`)

```sql
CREATE TABLE public.profiles (
  user_id uuid PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  display_name text NOT NULL CHECK (char_length(trim(display_name)) >= 2 AND char_length(trim(display_name)) <= 20),
  avatar_url text NULL,
  role text NOT NULL DEFAULT 'player' CHECK (role IN ('player', 'moderator', 'admin')),
  is_anonymous boolean NOT NULL DEFAULT true,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now()
);
```

### B. Profile Repository (`src/repositories/profileRepository.ts`)


## 4. Quyết Định Thiết Kế & Kiến Trúc (Architecture Decisions)

1. **Trigger `SECURITY DEFINER` tạo Profile tự động**:
   - Khi user được tạo trong `auth.users`, trigger chạy dưới quyền superuser để tạo profile.
   - Client không được cấp quyền `INSERT` trực tiếp qua REST API $\rightarrow$ triệt tiêu hoàn toàn nguy cơ client tạo profile rác hoặc profile giả mạo user khác.
2. **Bảo vệ cột hệ thống (`role`, `user_id`) bằng Trigger `BEFORE UPDATE`**:
   - Do Postgres RLS không hỗ trợ chặn theo cột độc lập trong policy UPDATE, việc sử dụng trigger `protect_profile_system_fields()` đảm bảo client không thể tự phong quyền `admin` hay `moderator`.
3. **Policy `SELECT` công khai cho toàn bộ người dùng**:
   - Hồ sơ người chơi (`display_name`, `avatar_url`, `role`) là dữ liệu công khai để hiển thị đối thủ trong phòng chờ, ván đấu đối kháng và bảng xếp hạng (P2.2 & P5.1).
4. **Không ghi đè tên tự đặt khi nâng cấp Google**:
   - Trong trigger `handle_user_update()`, tên từ Google chỉ được lấy nếu `display_name` hiện tại vẫn là tên mặc định `Khách-%`. Nếu người dùng đã tự đặt tên riêng trước đó, tên đó được bảo tồn nguyên vẹn.

## 5. Nợ Kỹ Thuật & Ghi Chú Tương Lai (Technical Debt)

1. **Quản lý Migration qua Supabase CLI**: Hiện tại các file migration được chạy thủ công qua SQL Editor. Ở Phase P2.2 (khi schema mở rộng sang trận đấu và rating), cân nhắc thiết lập `supabase link` để chạy migration tự động qua CLI.
2. **Component `PlayerBadge` chuẩn hóa**: Khối hiển thị avatar/tên trên `ProfilePage` hiện là bản tối giản P2.1c. Component `PlayerBadge` chính thức đa kích thước, tích hợp khung viền rank sẽ được xây dựng tại Phase P6.1.
3. **Đồng bộ thành tích Offline lên Cloud**: Dữ liệu thành tích trên `ProfilePage` hiện đọc từ `gameLocalData` cục bộ. Cơ chế đồng bộ dữ liệu local lên cloud sẽ được triển khai tại Phase P2.5.
4. **Hành vi OAuth trên iOS PWA Standalone**: Trên một số phiên bản iOS cũ, WebClip Sandbox có thể yêu cầu mở Safari tab riêng. Workaround chuẩn: hướng dẫn người dùng đăng nhập Google trên Safari trước khi bấm "Thêm vào Màn hình chính".
