## 3. HỢP ĐỒNG CÔNG KHAI (PUBLIC API CONTRACT)

### A. Database Schema & RLS Policies (`public.profiles`)

```sql
CREATE TABLE public.profiles (
  user_id uuid PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  display_name text NOT NULL CHECK (char_length(trim(display_name)) >= 2 AND char_length(trim(display_name)) <= 20),
  avatar_url text NULL,
  role text NOT NULL DEFAULT 'player' CHECK (role IN ('player', 'moderator', 'admin')), -- Dành cho P5.1
  is_anonymous boolean NOT NULL DEFAULT true,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now()
);

-- RLS Policies:
-- 1. SELECT: Cho phép tất cả (authenticated & anon) đọc hồ sơ công khai (dùng cho leaderboard, đối thủ).
-- 2. UPDATE: Chỉ chính chủ (auth.uid() = user_id) mới được sửa hồ sơ của mình.
-- 3. INSERT/DELETE: Không cấp cho client (Trigger SECURITY DEFINER tạo, CASCADE xóa).
-- 4. Trigger BEFORE UPDATE: Chặn đứng client tự ý sửa đổi `role` hoặc `user_id`.
```

## 4. QUYẾT ĐỊNH THIẾT KẾ (DESIGN DECISIONS)

| Quyết định                                                 | Lý do lựa chọn                                                                                                         | Phương án đã loại                                                                                       |
| :--------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------ |
| **Nâng cấp bằng `linkIdentity` thay vì sign-in mới**       | Bảo toàn 100% `user.id` của khách khi nâng cấp lên Google, không làm mất lịch sử và thành tích offline/online.         | Tạo user mới rồi xóa user cũ (dễ gây lỗi mồ côi dữ liệu và mất tiến trình chơi).                        |
| **Trigger `SECURITY DEFINER` tạo Profile**                 | Đảm bảo tính nhất quán (ACID); đóng hoàn toàn cổng client tự `INSERT` profile rác qua REST API.                        | Để frontend tự gọi `supabase.from('profiles').insert()` sau khi đăng ký (dễ bị bypass, race-condition). |
| **Chặn sửa `role`/`user_id` bằng Trigger `BEFORE UPDATE`** | Postgres RLS không hỗ trợ chặn theo cột độc lập trong lệnh UPDATE; trigger là giải pháp chặn triệt để role escalation. | Chỉ kiểm tra role ở client (cực kỳ nguy hiểm, dễ bị sửa payload request).                               |
| **Không dùng persist middleware cho `authStore`**          | Tránh desync dữ liệu vì `@supabase/supabase-js` đã tự động quản lý token và session an toàn trong `localStorage`.      | Bọc `persist` của Zustand (dễ gây xung đột token refresh ngầm của Supabase).                            |
| **Ping `/auth/v1/health` để chẩn đoán kết nối**            | Đo latency mạng chính xác mà không phụ thuộc DB schema hay phát sinh Disk I/O trên bảng Postgres.                      | Query `supabase.from('profiles').select('count')` (gây tốn quota database khi chưa cần thiết).          |
