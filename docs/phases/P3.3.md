## 1. TÓM TẮT (5 DÒNG)

- **Mục tiêu**: Xây dựng toàn bộ hệ thống phòng đấu mã 6 ký tự (`public.rooms`), `roomRepository`, giao diện sảnh đấu/màn hình chờ, Deep Link URL `/room/:code`, và màn hình ván đấu trực tuyến hoàn chỉnh `OnlineMatchScreen` cho game Cờ Caro.
- **Nguyên tắc Server là Nguồn Chân Lý Duy Nhất**: Mọi thay đổi bàn cờ chỉ đến từ Broadcast `move_accepted` của Trọng tài Server hoặc khi Resync từ `match_live_state`; client tuyệt đối không áp dụng optimistic move để tránh lệch thế cờ hay rollback giật quân.
- **Chống Áp Đôi & Lưới An Toàn Miss Broadcast**: So sánh nghiêm ngặt `payload.moveIndex === moveIndex + 1`; gói tin lặp bị bỏ qua (idempotent); gói tin nhảy cóc (`> local + 1`) tự động kích hoạt `matchRepository.getLiveState` kéo lại thế cờ chuẩn từ database.
- **Quản lý Vòng Đời & Quota Realtime**: Kênh `useMatchChannel` tự động ngắt kết nối (`enabled = false`) ngay khi trận đấu kết thúc (`isGameOver = true`); cảnh báo rời trận an toàn trong `GameShell`.

## 3. HỢP ĐỒNG CÔNG KHAI (PUBLIC CONTRACTS)

### A. TypeScript Interface `roomRepository` (`src/repositories/roomRepository.ts`)

```typescript
export interface RoomDto {
  readonly code: string;
  readonly expiresAt: string;
}

export interface JoinRoomResultDto {
  readonly matchId: string;
  readonly mySeat: number;
  readonly gameId: string;
}

export interface RoomStatusDto {
  readonly status: 'waiting' | 'matched' | 'cancelled' | 'expired';
  readonly matchId: string | null;
  readonly gameId: string;
  readonly mySeat: number;
}

export interface RoomInfoDto {
  readonly code: string;
  readonly hostId: string;
  readonly gameId: string;
  readonly status: string;
  readonly expiresAt: string;
}

export const roomRepository = {
  createRoom(gameId: string): Promise<RoomDto>;
  joinRoom(code: string): Promise<JoinRoomResultDto>;
  cancelRoom(code: string): Promise<boolean>;
  getRoomStatus(code: string): Promise<RoomStatusDto>;
  getRoomInfo(code: string): Promise<RoomInfoDto | null>;
  notifyRoomMatched(code: string, matchId: string, hostSeat: number): Promise<void>;
};
```

## 4. QUYẾT ĐỊNH THIẾT KẾ TRONG PHASE

| Quyết định                                              | Lý do lựa chọn                                                                                                                                                                                  | Phương án đã loại bỏ & Rủi ro                                                                                                            |
| :------------------------------------------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------- |
| **Quyết định Không Optimistic khi đánh nước đi**        | Game đối kháng theo lượt (turn-based) chịu được độ trễ 300-800ms. Chờ server phản hồi giúp mã nguồn đơn giản, triệt tiêu 100% rủi ro lệch thế cờ hay rollback giật quân khi nước đi bị từ chối. | _Optimistic Move đặt quân trước trên client_: Dễ gây giật màn hình khi server từ chối nước đi (VD: sai lượt, ô đã có quân, mất kết nối). |
| **Broadcast 'move_accepted' là Nguồn Chân Lý Duy Nhất** | Cả 2 bên nhận cùng 1 gói tin broadcast có `stateSerialized` từ Trọng tài Server để cập nhật bàn cờ đồng thời. Client không tự áp move từ API response.                                          | _Client tự áp move ngay khi nhận API response_: 2 bên cập nhật bàn cờ lệch nhịp nhau, dễ gây duplicate apply khi broadcast về sau.       |
| **Chống Áp Đôi & Idempotency**                          | So sánh nghiêm ngặt `payload.moveIndex === moveIndex + 1`. Gói tin có `moveIndex <= local` bị loại bỏ ngay lập tức.                                                                             | _Không kiểm tra moveIndex_: Có nguy cơ áp lại nước đi cũ khi mạng gửi lặp gói tin.                                                       |
| **Lưới An Toàn Auto-Resync khi Miss Broadcast**         | Khi phát hiện `payload.moveIndex > local + 1` (bị nhảy cóc do rớt gói tin mạng), hệ thống tự động gọi `matchRepository.getLiveState(matchId)` để kéo lại bàn cờ mới nhất từ DB.                 | _Bỏ qua gói tin nhảy cóc_: Người chơi bị kẹt thế cờ cũ và không thể tiếp tục đánh các nước tiếp theo.                                    |
| **Tự động ngắt kết nối Transport khi Kết Thúc Trận**    | Khi `isGameOver = true`, hook `useMatchChannel` nhận `enabled = false` $\rightarrow$ ngắt kết nối WebSocket Realtime ngay lập tức.                                                              | _Giữ kết nối sau khi trận xong_: Lãng phí Quota Supabase Realtime Free Tier.                                                             |
