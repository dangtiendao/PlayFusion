> **TUYỆT ĐỐI KHÔNG CHẠY `npm run test:rls` TRÊN MÔI TRƯỜNG PRODUCTION**, vì bộ test tự động tạo và xóa user thật. Nghiệm thu trên PROD được thực hiện qua các lệnh kiểm kê SQL.

### A. Thứ Tự Chạy Migration Trên Project PROD

1. Mở **SQL Editor** trên Supabase Dashboard của dự án **PROD**.
2. Chạy lần lượt:
   - `0009_rls_hardening.sql` $\rightarrow$ Run (Vá RLS profiles, chuẩn hóa role `TO authenticated`).
   - `0010_hardening.sql` $\rightarrow$ Run (Thu hồi quyền anon, khóa default privileges, chuẩn hóa 10 functions).

---

### B. Câu Lệnh SQL Đối Chiếu Toàn Diện DEV vs PROD

Dán query sau vào SQL Editor trên cả 2 môi trường để đối chiếu:

```sql
-- 1. KIỂM TRA 15 BẢNG ĐỀU BẬT RLS (Kỳ vọng: 15 bảng đều rls_enabled = true)
SELECT c.relname, c.relrowsecurity
FROM pg_class c
JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE n.nspname = 'public' AND c.relkind = 'r'
  AND c.relname IN ('profiles', 'games', 'seasons', 'matches', 'match_participants', 'player_ratings', 'wallets', 'wallet_transactions', 'shop_items', 'user_inventory', 'user_equipped', 'purchases', 'audit_logs', 'system_config', 'orders')
ORDER BY c.relname;

-- 2. KIỂM TRA QUYỀN CỦA VAI TRÒ ANON ĐÃ BỊ THU HỒI HOÀN TOÀN (Kỳ vọng: 0 dòng)
SELECT table_name, privilege_type
FROM information_schema.role_table_grants
WHERE grantee = 'anon' AND table_schema = 'public';

-- 3. KIỂM TRA 10 FUNCTIONS ĐÃ KHÓA SEARCH_PATH = public (Kỳ vọng: 10 functions)
SELECT proname, proconfig
FROM pg_proc p
JOIN pg_namespace n ON n.oid = p.pronamespace
WHERE n.nspname = 'public'
  AND proname IN ('handle_new_user', 'handle_user_update', 'handle_new_profile_wallet', 'handle_new_profile_starter_cosmetics', 'audit_wallet_balance', 'handle_updated_at', 'protect_profile_system_fields', 'prevent_wallet_transactions_mutation', 'prevent_purchases_mutation', 'prevent_audit_logs_mutation')
ORDER BY proname;
```

## 7. ĐẦU VÀO GỢI Ý CHO PHASE KẾ TIẾP (PHASE P2.5 — CLIENT REPOSITORIES & DATA ACCESS LAYER)

Khi bắt đầu **Phase P2.5 (Client Repositories & Data Access Layer)**, kỹ sư cần nắm rõ các ràng buộc bất biến:

1. **Khuôn Khổ RLS**: Toàn bộ thao tác truy vấn dữ liệu từ frontend qua `src/repositories/` phải tuân thủ nghiêm ngặt ma trận `docs/security/rls-matrix.md`.
2. **Cơ Chế Đồng Bộ Trận Đấu Offline Lên Cloud**:
   - Do bảng `matches`, `match_participants` và `player_ratings` **bị cấm ghi 100% từ client**, client không thể tự gọi `supabase.from('matches').insert(...)`.
   - Thiết kế P2.5 cần định hình rõ: Việc đồng bộ kết quả ván cờ sẽ được thực hiện qua RPC `SECURITY DEFINER` hoặc gọi Endpoint Edge Function `settle_match` (P4.2).
3. **Thao Tác Đổi Trang Bị (Equip)**:
   - Được phép gọi trực tiếp qua client: `supabase.from('user_equipped').upsert({ slot_key, item_id, user_id })` (DB sẽ tự động kiểm tra sở hữu qua `WITH CHECK`).
