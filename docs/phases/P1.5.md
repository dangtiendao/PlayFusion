## 3. Hợp Đồng Công Khai (Public API Contract)

### A. Quy ước Khóa Lưu Trữ & Phân Nhóm Chế Độ

- **Prefix Storage**: `wgh:v1:game:{gameId}:{section}` (quản lý tự động bởi `buildGameDataKey`).
- **Các phân vùng (`section`)**:
  - `'stats'`: Thống kê thành tích dài hạn (`GameLocalStats`).
  - `'lastConfig'`: Cấu hình ván đấu gần nhất (`T`).
  - `'savedMatch'`: Trạng thái ván đấu dở dang (`SavedMatch`).
  - `'history'`: Mảng lịch sử các ván đấu đã kết thúc (`LocalMatchRecord[]`).
- **Quy ước `modeKey`**: Do từng game tự định nghĩa chuỗi khóa (ví dụ: `'vs_ai:easy'`, `'vs_ai:medium'`, `'vs_ai:hard'`, `'local_pvp'`).

### B. Interface & Kiểu Dữ Liệu Generic

```typescript
export interface GameModeStats {
  matches: number;
  wins: number;
  losses: number;
  draws: number;
}

export interface GameLocalStats {
  totalMatches: number;
  wins: number;
  losses: number;
  draws: number;
  byMode: Record<string, GameModeStats>;
  currentStreak: number;
  bestStreak: number;
  updatedAt: string;
}

export interface SavedMatch {
  schemaVersion: 1;
  engineStateSerialized: string;
  gameConfig: unknown;
  sessionExtra?: unknown;
  savedAt: string;
}

export interface LocalMatchRecord {
  id: string;
  finishedAt: string;
  modeKey: string;
  outcome: 'win' | 'loss' | 'draw' | 'none';
  summary: unknown;
  movesSerialized?: string;
}
```

### C. Chữ Ký Hàm Public Exported

```typescript
// Thống kê thành tích
export function getStats(gameId: string): GameLocalStats;
export function recordResult(
  gameId: string,
  modeKey: string,
  outcome: 'win' | 'loss' | 'draw' | 'none',
): GameLocalStats;

// Cấu hình gần nhất
export function getLastConfig<T>(gameId: string): T | null;
export function setLastConfig<T>(gameId: string, config: T): void;

// Ván đấu dở dang (Auto-save & Recovery)
export function saveMatch(gameId: string, data: SavedMatch): void;
export function getSavedMatch(gameId: string): SavedMatch | null;
export function clearSavedMatch(gameId: string): void;

// Lịch sử ván đấu
export function getHistory(gameId: string): LocalMatchRecord[];
export function appendHistory(
  gameId: string,
  record: Omit<LocalMatchRecord, 'id' | 'finishedAt'> & { id?: string; finishedAt?: string },
  maxRecords?: number,
): LocalMatchRecord[];

// Dọn dẹp & Quản lý
export function hasGameData(gameId: string): boolean;
export function clearGameData(gameId: string): void;
```

## 4. Quyết Định Thiết Kế & Tính Toán Kỹ Thuật

1. **Ranh Giới Kiến Trúc Generic 100%**:
   - `src/core/gameLocalData.ts` tuyệt đối không import từ `src/games/` và không chứa bất kỳ từ khóa đặc thù nào của game (`grep -i 'caro' src/core/gameLocalData.ts` = 0 kết quả). Mọi game tương lai (Ô ăn quan, Gõ phím) sẽ tái sử dụng nguyên vẹn.
2. **Kỷ Luật Tiết Kiệm Bộ Nhớ — Giới Hạn Trần FIFO 20 Bản Ghi**:
   - Dung lượng localStorage của trình duyệt bị giới hạn ở mức ~5MB. Việc giới hạn 20 bản ghi gần nhất đảm bảo lưu trữ cực kỳ gọn nhẹ (~10-20KB), ngăn chặn nguy cơ tràn bộ nhớ của trình duyệt.
3. **Pipeline Khôi Phục Ván Dở 6 Bước An Toàn (Fail-Safe Pipeline)**:
   - Khi khôi phục ván đấu: (a) Validate config $\rightarrow$ (b) Deserialize Engine State $\rightarrow$ (c) Đối chiếu chéo `isTerminal.over === false` $\rightarrow$ (d) Khôi phục Session Extra $\rightarrow$ (e) Chuyển state sang `playing` $\rightarrow$ (f) Bất kỳ bước nào phát hiện sai lệch $\rightarrow$ tự động dọn sạch key hỏng và hiển thị Toast thông báo, tuyệt đối không gây crash ứng dụng.
4. **Hiệu Năng Auto-Save**:
   - Chuỗi serialize bàn cờ 15x15 chỉ ~300 bytes JSON, thời gian ghi storage sau mỗi nước đi hợp lệ đo được <1ms, hoàn toàn không gây drop frame hay ảnh hưởng đến độ mượt của UI.

## 5. Nợ Kỹ Thuật (Technical Debt)

1. **Chuẩn Hóa Format `movesSerialized` (Replay Viewer - P8.1)**:
   - Hiện tại Caro lưu danh sách nước đi dạng chuỗi phân cách bởi dấu phẩy (`0,15,1,16...`). Ở Phase P8.1, định dạng nén nước đi sẽ được chuẩn hóa thành format replay chung để hỗ trợ tua lại ván đấu từng nước.
2. **Tính Năng Undo (Đi Lại Nước Cờ)**:
   - Ghi nợ sang backlog tính năng mở rộng. Không đưa vào phạm vi Nhóm 1 để tránh làm phức tạp state machine và đảm bảo tiến độ chuyển sang Nhóm 2.
3. **Đồng Bộ Dữ Liệu Lên Cloud (P2.5 & P2.6)**:
   - Hiện tại dữ liệu hoàn toàn lưu cục bộ (Local-first). Khi lên Phase P2 (Online & Auth), tầng `gameLocalData` sẽ là nguồn dữ liệu offline và sẽ có cơ chế sync/merge với Supabase Database khi người dùng đăng nhập.
