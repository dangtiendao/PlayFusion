## 1. TÓM TẮT

Phase P0.3 đã hoàn thiện trọn vẹn chu trình Tự động hóa Phát triển & Vận hành (CI/CD) cho Web Game Hub. Thiết lập GitHub Actions workflow kiểm soát 6 cổng chất lượng nghiêm ngặt (Lint, Format, Typecheck, Dependency Rules, Unit Tests, Build); cấu hình máy chủ Cloudflare Pages với cơ chế fallback SPA (`_redirects`), bộ nhớ đệm bất biến và bảo mật (`_headers`); thiết lập cơ chế Preview Deployment cho mọi nhánh tính năng; và kích hoạt quy ước bảo vệ nhánh "CI đỏ tuyệt đối không merge". Mọi pipeline đều đạt trạng thái sẵn sàng cho sản xuất.

## 6. HƯỚNG DẪN VẬN HÀNH

### A. Kịch bản Kiểm chứng End-to-End (Quy trình làm việc hàng ngày)

1. **Phát triển tính năng**:
   ```bash
   git checkout -b feat/ten-tinh-nang
   # Thực hiện code...
   npm run typecheck && npm run lint && npm run test
   git add . && git commit -m "feat: mo ta tinh nang"
   git push origin feat/ten-tinh-nang
   ```
2. **Review qua Preview Deployment**:
   - Truy cập `https://feat-ten-tinh-nang.<project-name>.pages.dev` để kiểm tra giao diện trực tiếp trên điện thoại/desktop trước khi tạo PR.
3. **Merge vào Production**:
   - Tạo Pull Request $\rightarrow$ Đợi GitHub Actions hiển thị dấu tích xanh ✅.
   - Nhấn **Merge** vào `master`/`main` $\rightarrow$ Cloudflare Pages tự động triển khai lên `https://<project-name>.pages.dev`.

### B. Thiết lập GitHub Branch Protection Rule (Khuyến nghị bảo vệ nhánh chính)

1. Truy cập GitHub Repo $\rightarrow$ **Settings** $\rightarrow$ **Branches** $\rightarrow$ **Add branch protection rule**.
2. **Branch name pattern**: `master` (hoặc `main`).
3. Tích chọn:
   - ✅ `Require a pull request before merging`.
   - ✅ `Require status checks to pass before merging` $\rightarrow$ Chọn check: `Kiểm Tra Chất Lượng & Build`.
   - ✅ `Require branches to be up to date before merging`.
4. Nhấn **Save changes**.

## 7. ĐẦU VÀO GỢI Ý CHO PHASE KẾ TIẾP (P0.4 — Mobile-First Responsive Shell & Component Foundation)

Phase **P0.4** bắt đầu xây dựng khung giao diện chính thức cho Web Game Hub. Cần nắm rõ các ràng buộc từ P0.1, P0.2 và P0.3:

1. **Hosting & Preview**: Mọi component xây dựng tại P0.4 sẽ có thể kiểm thử trực tiếp trên điện thoại thật thông qua Preview URL của Cloudflare Pages.
2. **Design Tokens có sẵn**: Bảng màu ngữ nghĩa (`primary`, `surface`, `surface-dark`, `danger`, `success`) và biến safe-area (`--sat`, `--sar`, `--sab`, `--sal`) đã được thiết lập sẵn tại `tailwind.config.ts` và `src/index.css`.
3. **Quy tắc Vùng Chạm Mobile**: Tất cả các interactive components (Button, Bottom Navigation Bar, Modal triggers) phải đảm bảo chiều cao tối thiểu $\ge 44\text{px}$ (`min-h-[44px]`) để tối ưu thao tác ngón tay cái.
4. **Ranh giới Kiến trúc**: Toàn bộ UI components đặt tại `src/components/`, layout shell đặt tại `src/core/` hoặc `src/components/`, không được vi phạm luật phân tầng `check:deps`.
