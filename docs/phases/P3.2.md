## 3. HỢP ĐỒNG CÔNG KHAI (PUBLIC CONTRACTS)

### A. DDL Bảng `public.match_live_state`

```sql
CREATE TABLE public.match_live_state (
  match_id uuid PRIMARY KEY REFERENCES public.matches(id) ON DELETE CASCADE,
  state_serialized text NOT NULL,                    -- engine.serialize(state hiện tại)
  move_index int NOT NULL DEFAULT 0 CHECK (move_index >= 0), -- Số nước đã áp dụng (Khóa lạc quan + Idempotency key)
  current_seat smallint NOT NULL CHECK (current_seat >= 0),   -- Ghế người chơi đang đến lượt đi (0-indexed)
  moves_serialized text NOT NULL DEFAULT '',         -- moves-codec tích lũy
  turn_deadline timestamptz NULL,                    -- Khai báo sẵn cho P3.4 đồng hồ đếm ngược
  updated_at timestamptz NOT NULL DEFAULT now()
);
```

### B. Chữ Ký RPC `public.create_test_online_match(p_opponent_id uuid) RETURNS uuid`

- **Vai trò**: Tạo ván đấu test online 1v1 cho 2 user (Caller: Seat 0, Opponent: Seat 1).
- **Bảo mật**: `SECURITY DEFINER`, `search_path = ''`, chỉ cấp quyền `EXECUTE` cho `authenticated`.
- **Ghi chú**: Dev-scaffold sẽ được thay thế ở Phase P3.3 bởi luồng phòng đấu 6 ký tự rồi DROP.

### C. Quy Ước Response JSON Bắt Buộc Cho Toàn Bộ Edge Functions

- **Thành công (HTTP 200)**: `{ "ok": true, "data": { ... } }`
- **Thất bại (HTTP 400 / 401 / 403 / 500)**: `{ "ok": false, "error": { "code": "ERROR_CODE", "message": "Mô tả lỗi" } }`

## 7. ĐẦU VÀO GỢI Ý CHO PHASE KẾ TIẾP [P3.2C: EDGE FUNCTION REFEREE SERVER-SIDE]

1. **Schema & RPC sẵn sàng 100%**: Bảng `match_live_state` đã sẵn sàng nhận state nén và `move_index`.
2. **Nhiệm vụ trọng tâm Phase P3.2c**:
   - Xây dựng Edge Function `supabase/functions/referee/index.ts`:
     - **Action `init`**: Nhận `matchId` $\rightarrow$ Nạp Caro Engine init $\rightarrow$ Ghi `match_live_state` (move_index = 0).
     - **Action `submit_move`**:
       1. Nhận `{ matchId, move, expectedMoveIndex }`.
       2. Xác thực JWT người gửi = `current_seat` trong `match_participants`.
       3. Đọc `state_serialized` từ `match_live_state` $\rightarrow$ Deserialize thành `CaroState`.
       4. Kiểm tra `move` hợp lệ qua `caroEngine.legalMoves` $\rightarrow$ Gọi `caroEngine.applyMove`.
       5. Kiểm tra `isTerminal` (thắng/thua/hòa).
       6. Cập nhật `match_live_state` (`move_index = expectedMoveIndex + 1`, `state_serialized`, `moves_serialized`).
       7. Nếu kết thúc trận $\rightarrow$ Cập nhật `matches.ended_at` và `match_participants.is_winner`.
       8. Phát sóng thông điệp kết quả qua Supabase Realtime Broadcast `match:{matchId}` tới cả 2 client.
