## 1. TÓM TẮT (5 DÒNG)

1. **Mục tiêu**: Xây dựng kinh tế xu, điểm danh hàng ngày 1 chạm, sổ cái giao dịch và cơ chế chống farm tiền tệ hai tầng.
2. **Luật chống farm**: Trần ngày $\le 500$ xu (enforce trong DB sau khi lock ví) + Giảm thưởng khi gặp lại ($100\% \rightarrow 50\% \rightarrow 0\%$).
3. **Bảo mật & Idempotency**: RPC `claim_daily_bonus` lũy suy theo múi giờ VN (`Asia/Ho_Chi_Minh`), trigger chặn sửa sổ cái, RLS chính chủ.
4. **Giao diện & Trải nghiệm**: Trang `/wallet` mobile-first, 4 khối tách biệt, bộ từ điển nhãn `txnLabels.ts` thuần tiếng Việt, cache client TTL 15s.
5. **Kết quả nghiệm thu**: 87 test files Vitest (659 tests) + 53 Deno tests + RLS tests + Integration tests đạt tỷ lệ vượt qua 100%.

## 3. HỢP ĐỒNG CÔNG KHAI (PUBLIC CONTRACTS)

### 3.1. Database RPCs & Schema

```sql
-- 1. Điểm danh hàng ngày (Client gọi trực tiếp)
-- Return: JSON {"claimed": boolean, "already"?: boolean, "coins"?: number, "balance": number}
SELECT public.claim_daily_bonus();

-- 2. Kết toán trận đấu (Chỉ referee service_role được gọi)
-- Return: JSON {"applied": boolean, "entries": [{"user_id": "uuid", "coins_applied": 20, "capped": true}]}
SELECT public.apply_match_settlement(p_payload jsonb);
```

### 3.2. TypeScript API Repository (`src/repositories/walletRepository.ts`)

```typescript
export interface WalletTxn {
  readonly id: string;
  readonly userId: string;
  readonly amount: number;
  readonly balanceAfter: number;
  readonly type:
    | 'match_reward'
    | 'match_penalty'
    | 'daily_bonus'
    | 'admin_adjust'
    | 'purchase'
    | 'topup'
    | 'refund';
  readonly refType: string | null;
  readonly refId: string | null;
  readonly idempotencyKey: string;
  readonly createdAt: string;
}

export interface WalletTxnCursor {
  readonly createdAt: string;
  readonly id: string;
}
export interface WalletTxnPage {
  readonly entries: readonly WalletTxn[];
  readonly nextCursor: WalletTxnCursor | null;
  readonly hasMore: boolean;
}
export interface ClaimBonusResult {
  readonly claimed: boolean;
  readonly already?: boolean;
  readonly coins?: number;
  readonly balance: number;
}

// Hàm export cho các module khác
export function getMyBalance(forceRefresh?: boolean): Promise<number>;
export function getMyTransactions(
  cursor?: WalletTxnCursor | null,
  pageSize?: number,
): Promise<WalletTxnPage>;
export function claimDailyBonus(): Promise<ClaimBonusResult>;
export function getDailyBonusStatus(): Promise<boolean>;
export function invalidateWalletCache(): void;
```

_Ví dụ gọi ngắn_:

```typescript
import { walletRepository, invalidateWalletCache } from '@/repositories/walletRepository';

// Lấy số dư ví
const balance = await walletRepository.getMyBalance();

// Xóa cache sau ván đấu
invalidateWalletCache();
```

## 4. QUYẾT ĐỊNH THIẾT KẾ (DESIGN DECISIONS)

| Vấn đề                        | Quyết định chọn                                                          | Lý do                                                                             | Phương án đã loại                                                                 |
| :---------------------------- | :----------------------------------------------------------------------- | :-------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------- |
| **Enforce trần ngày**         | Tính trong DB Transaction sau `SELECT ... FOR UPDATE` ví.                | Chống tuyệt đối Race Condition khi 2 ván settle song song trên 2 worker.          | Tính ở Edge Function trước khi ghi DB (Dễ lọt race condition).                    |
| **Múi giờ tính ngày**         | Thống nhất `Asia/Ho_Chi_Minh` ở cả 3 tầng (DB Settle, DB Bonus, Client). | Đảm bảo mốc 00:00 AM VN đồng nhất, không bị lệch giờ giữa các múi giờ UTC/Client. | Dùng múi giờ UTC hoặc Date local của thiết bị (Lệch ngày).                        |
| **Dặm thưởng lặp cặp**        | Tính trong `settle.ts` qua truy vấn cặp đấu trong ngày.                  | Không làm phức tạp hóa DB schema, sai số đua hiếm gặp chỉ là vài xu (chấp nhận).  | Tạo bảng riêng `daily_pair_counters` với row-lock (Nặng DB, lãng phí tài nguyên). |
| **Độc lập Rating Elo**        | Giảm thưởng lặp cặp & trần ngày **chỉ áp dụng vào xu**.                  | Bảo toàn tính công bằng của thuật toán Elo xếp hạng kỹ năng người chơi.           | Giảm cả điểm Elo theo số ván đấu (Phá vỡ hệ thống Rank).                          |
| **Kiểm tra status điểm danh** | Client tự `SELECT 1` dòng ledger `daily:{me}:{today}` qua RLS.           | Tận dụng chính sách RLS `authenticated`, không cần viết thêm RPC thứ hai.         | Tạo RPC `get_daily_bonus_status` (Thừa thãi, tăng tải bảo trì).                   |

## 7. ĐẦU VÀO GỢI Ý CHO PHASE KẾ TIẾP (PHASE P4.6: QUẢN LÝ MÙA GIẢI)

1. **Ràng buộc Mùa Giải**: Bảng `seasons` đã có ràng buộc `UNIQUE (is_active) WHERE is_active = true` (Migration 0016).
2. **Settle tự động gắn `season_id`**: Hàm `join_room` tự động gán `season_id` đang mở vào `matches.season_id`. Settle chỉ kết toán ván đấu khi `season_id` không null.
3. **Công thức Soft-Reset Rating khi sang mùa mới**:
   $$\text{Rating}_{\text{new}} = \text{round}(0.6 \times \text{Rating}_{\text{old}} + 480)$$
4. **Huy hiệu mùa & Lịch sử rank**: Phase P4.6 sẽ bổ sung bảng lưu trữ kết quả cuối mùa và cấp khung viền/danh hiệu mùa cho các kỳ thủ đủ điều kiện ( $\ge 10$ trận).
