## 3. HỢP ĐỒNG CÔNG KHAI (PUBLIC CONTRACTS)

### 3.1. Database Schema & Stored Functions

#### Bảng `public.user_season_badges` (Kỷ vật vĩnh viễn):

```sql
CREATE TABLE public.user_season_badges (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid NOT NULL REFERENCES public.profiles(user_id),
  season_id smallint NOT NULL REFERENCES public.seasons(id),
  game_id text NOT NULL REFERENCES public.games(id),
  final_rating numeric NOT NULL,
  final_tier text NOT NULL,
  final_rank int NULL,
  games_played int NOT NULL,
  wins int NOT NULL,
  losses int NOT NULL,
  draws int NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT uq_user_season_badges_user_season_game UNIQUE (user_id, season_id, game_id)
);
-- RLS: SELECT công khai; Deny-write client; Trigger Append-Only.
```

#### Bảng `public.rating_decay_log` (Nhật ký trừ điểm):

```sql
CREATE TABLE public.rating_decay_log (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid NOT NULL REFERENCES public.profiles(user_id),
  game_id text NOT NULL REFERENCES public.games(id),
  season_id smallint NOT NULL REFERENCES public.seasons(id),
  week_key text NOT NULL, -- 'IYYY-IW' theo Asia/Ho_Chi_Minh
  points int NOT NULL CHECK (points > 0),
  rating_before numeric NOT NULL,
  rating_after numeric NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT uq_rating_decay_log_user_game_season_week UNIQUE (user_id, game_id, season_id, week_key)
);
-- RLS: SELECT chính chủ (auth.uid() = user_id); Deny-write client; Trigger Append-Only.
```

## 4. QUYẾT ĐỊNH THIẾT KẾ (DESIGN DECISIONS)

1. **Soft-Reset Khởi Tạo Rating Mùa Mới**:
   - Áp dụng công thức nén điểm chuẩn $R_{\text{mới}} = \text{ROUND}(0.6 \times R_{\text{cũ}} + 480)$.
   - `best_rating` khởi đầu của mùa mới được đặt bằng đúng điểm số xuất phát $R_{\text{mới}}$ (kỷ lục đỉnh cao là phạm vi của từng mùa giải).
   - Người chơi có $0$ trận ở mùa cũ không bị seed rác vào bảng `player_ratings` của mùa mới (khi họ chơi ván đầu tiên ở mùa mới, hệ thống tự động khởi tạo dòng 1200 chuẩn).
2. **Xử Lý Trận Đấu Dở Xuyên Mùa (In-Flight Matches Decoupling)**:
   - Khi ván đấu được khởi tạo, `matches.season_id` được ghi nhận cố định theo mùa giải lúc tạo phòng.
   - Hàm `apply_match_settlement` kết toán điểm số dựa vào `matches.season_id` của chính trận đó $\rightarrow$ Ván đấu tạo ở Mùa 1 kết thúc sau khi Mùa 2 đã mở vẫn kết toán chính xác vào dòng `player_ratings` của Mùa 1, bảo đảm toàn vẹn $100\%$.
3. **Luật Trừ Điểm Bỏ Đấu (Rating Decay)**:
   - Chỉ áp dụng cho kỳ thủ bậc cao ($\text{Rating} > 1600$, Kim Cương trở lên), đã hoàn thành định hạng ($\ge 10$ trận) và không thi đấu $> 30$ ngày.
   - Giữ sàn 1600: Không bao giờ làm kỳ thủ rớt xuống dưới mốc Kim Cương chỉ vì decay ($points = \text{LEAST}(10, \text{Rating} - 1600)$).
   - `best_rating` giữ nguyên (kỷ lục thành tích không bị decay).
4. **Quy Trình Đóng Mùa Bằng Tay (Human-in-the-loop SOP)**:
   - Không tự động hóa lịch đóng mùa bằng cron job ngầm để tránh rủi ro đóng nhầm khi mùa giải đang có sự kiện hoặc cần gia hạn. Đóng mùa được thực hiện bởi Admin/DevOps qua SOP `docs/testing/P4.6-close-season-drill.md`.
