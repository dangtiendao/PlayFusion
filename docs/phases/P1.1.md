## 3. HỢP ĐỒNG CÔNG KHAI (PUBLIC CONTRACTS)

### A. Interface `CaroState`, `CaroMove`, và `CaroOptions` (`types.ts`)

```typescript
export interface CaroOptions {
  readonly boardSize: number; // Mặc định: 15 (Hợp lệ: 5..25)
  readonly winLength: number; // Mặc định: 5 (Hợp lệ: 3..boardSize)
  readonly blockedTwoEndsRule: boolean; // Mặc định: true (Luật VN: chặn 2 đầu không thắng)
  readonly allowOverline: boolean; // Mặc định: true (6+ quân liên tiếp tính thắng)
}

export interface CaroState {
  readonly board: readonly number[]; // Mảng 1D length size*size (-1: trống, 0: Seat 0/X, 1: Seat 1/O)
  readonly currentPlayer: PlayerIndex; // 0 hoặc 1
  readonly moveCount: number; // Tổng số nước đi đã thực hiện
  readonly lastMove: number | null; // Flat index nước đi gần nhất (0..size*size-1)
  readonly options: CaroOptions; // Bất biến sau khởi tạo
}

export type CaroMove = number; // Flat index (0..size*size-1)
```

### B. Chữ Ký Logic Thắng Cờ (`win-check.ts`)

```typescript
export interface WinResult {
  readonly winner: PlayerIndex;
  readonly line: readonly number[]; // Danh sách flat index các ô cờ tạo thành chuỗi thắng
}

export function checkWinAt(
  board: readonly number[],
  size: number,
  index: number,
  options: CaroOptions,
): WinResult | null;

export function checkWinFullScan(
  board: readonly number[],
  size: number,
  options: CaroOptions,
): WinResult | null;
```

### C. Định Dạng Serialization Nén (`serialize` / `deserialize`)

Chuỗi nén gồm 9 trường ngăn cách bởi dấu `:`:

```text
v1:<boardSize>:<winLength>:<blockedTwoEnds>:<allowOverline>:<currentPlayer>:<moveCount>:<lastMove>:<boardRLE>
```

- **Ví dụ**: Bàn 15x15 trống: `v1:15:5:1:1:0:0:-1:225.` (23 bytes); Bàn 60 nước: `v1:15:5:1:1:0:60:112:55.x2.o1.x...80.` (~120 bytes).

### D. Thứ Tự Validate & Mã Lỗi `EngineError` trong `applyMove`

```typescript
// Thứ tự ném lỗi: GAME_OVER -> WRONG_TURN -> ILLEGAL_MOVE (out-of-bounds) -> ILLEGAL_MOVE (occupied)
try {
  const nextState = caroEngine.applyMove(state, move, playerIndex);
} catch (err) {
  if (err instanceof EngineError) {
    console.error(err.code, err.message); // Map HTTP 400 tại Server Edge Function P3.2
  }
}
```

## 4. QUYẾT ĐỊNH THIẾT KẾ

| Quyết định                               | Lý do lựa chọn                                                                                                                 | Phương án đã loại bỏ & Lý do loại                                                           |
| :--------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------ |
| **Mảng 1D phẳng (`number[]`)**           | Truy cập `y * size + x` cực nhanh, tối ưu bộ nhớ đệm CPU cache locality, nén RLE tức thì.                                      | _Mảng 2D `number[][]`_: Cồng kềnh, tốn bộ nhớ GC, serialize chậm.                           |
| **Quét $\mathcal{O}(1)$ qua `lastMove`** | `isTerminal` chỉ quét 4 hướng quanh nước vừa đi, tốc độ tính toán siêu nhanh cho AI duyệt hàng triệu node.                     | _Quét toàn bàn $\mathcal{O}(N^2)$_: Rất chậm, làm nghẽn Worker AI khi Minimax tìm kiếm sâu. |
| **Mép bàn không tính là chặn**           | Đúng luật truyền thống: 5 quân sát biên chỉ bị chặn 1 đầu $\rightarrow$ Vẫn thắng. Chỉ chặn 2 đầu bởi quân địch mới hủy thắng. | _Mép bàn tính là chặn_: Gây ức chế và sai lệch với luật chơi Caro Việt Nam thực tế.         |
| **Move là `number` (flat index)**        | Tối ưu hóa băng thông truyền tin Realtime và lưu trữ Move (chỉ 1-3 byte).                                                      | _Move là `{ x, y }`_: Tốn dung lượng payload JSON truyền qua mạng.                          |
