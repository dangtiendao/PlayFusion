## 3. HỢP ĐỒNG CÔNG KHAI (PUBLIC CONTRACTS)

### A. Tầng Repositories & Pure Rules

```typescript
// 1. Đọc thống kê tất cả các game của người dùng hiện tại
import { getMyGameStats } from '@/repositories/statsRepository';
const stats: PlayerGameStats[] = await getMyGameStats();

// 2. Tính toán trạng thái hiển thị Winrate
import { computeWinrateView, MIN_MATCHES_FOR_WINRATE } from '@/core/statsRules';
const winrateResult = computeWinrateView(modeStats);
// -> { kind: 'visible', winratePct: 66.7 } HOẶC { kind: 'hidden', needMore: 3 }

// 3. Gộp thống kê Đấu Máy từ 3 level
import { aggregateVsAi } from '@/core/statsRules';
const { overall, byLevel } = aggregateVsAi(stats.byModeKey);

// 4. Chọn nhóm thống kê chính (Hero Stats)
import { pickPrimaryModeStats } from '@/core/statsRules';
const primary = pickPrimaryModeStats(stats.byModeKey);
```

## 4. QUYẾT ĐỊNH THIẾT KẾ TRONG PHASE

| Quyết định                            | Lý do                                                                                                                             | Phương án đã loại                                                                                       |
| :------------------------------------ | :-------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------ |
| **Client-side Aggregate (P2.6a)**     | Tránh migration mới, dữ liệu < 15KB/user, xử lý in-memory < 1ms, linh hoạt mở rộng modeKey. Giới hạn trần `.limit(1000)` an toàn. | Viết Stored Procedure / Materialized View ngay $\rightarrow$ Làm phức tạp DB khi chưa có nhiều dữ liệu. |
| **Ẩn Winrate khi < 10 trận**          | Tránh tỷ lệ thắng bị méo mó/ảo khi số lượng mẫu quá ít (ví dụ thắng 1/1 ván = 100%).                                              | Hiện ngay từ ván 1 $\rightarrow$ Thiếu chính xác và gây hiểu lầm.                                       |
| **Hòa không tính vào mẫu số Winrate** | Công thức `wins / (wins + losses)`. Kết quả hòa phản ánh sự cân bằng kỹ năng, không phải là thất bại.                             | Chia cho tổng số ván (kể cả hòa) $\rightarrow$ Ép người chơi cờ coi ván hòa như thua.                   |
| **Local PvP chỉ đếm số ván**          | 2 người chơi chung 1 máy không phải thành tích cá nhân của chủ tài khoản (P1.5a). Trận đấu mang tính giải trí chung.              | Ghi nhận thắng/thua vào profile $\rightarrow$ Gian lận/cày ảo điểm số.                                  |
| **Không có Winrate chung toàn Hub**   | Thể loại đối kháng (Caro) và Puzzle (Xếp hình) không thể cộng dồn tỷ lệ thắng vì không cùng hệ quy chiếu.                         | Tính winrate trung bình toàn server $\rightarrow$ Số liệu vô nghĩa về mặt toán học.                     |

## 6. HƯỚNG DẪN VẬN HÀNH

- **Môi trường & Biến môi trường**: Không yêu cầu biến môi trường mới (sử dụng `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`).
- **Migration**: Không yêu cầu migration mới trong Phase P2.6.
- **SQL Đối Soát Thống Kê (DEV & PROD)**:
  ```sql
  SELECT
    m.game_id,
    CASE
      WHEN m.mode = 'vs_ai' AND mp.bot_level IS NOT NULL THEN 'vs_ai:' || mp.bot_level
      ELSE m.mode
    END AS mode_key,
    COUNT(*) AS total_matches,
    CASE WHEN m.mode = 'local_pvp' THEN 0 ELSE COUNT(*) FILTER (WHERE mp.result = 'win') END AS wins,
    CASE WHEN m.mode = 'local_pvp' THEN 0 ELSE COUNT(*) FILTER (WHERE mp.result = 'loss') END AS losses,
    COUNT(*) FILTER (WHERE mp.result = 'draw') AS draws
  FROM public.match_participants mp
  JOIN public.matches m ON mp.match_id = m.id
  WHERE mp.user_id = auth.uid()
  GROUP BY m.game_id, mode_key
  ORDER BY m.game_id, mode_key;
  ```
