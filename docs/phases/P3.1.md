## 3. HỢP ĐỒNG CÔNG KHAI (PUBLIC CONTRACTS)

### A. Giao Diện `MatchChannel` & Factory Function

```typescript
import {
  createMatchChannel,
  type MatchChannel,
  type PresenceMember,
  type MatchChannelHandlers,
} from '@/transport';

const self: PresenceMember = {
  userId: 'user-uuid',
  displayName: 'Nguyễn Văn A',
  joinedAt: new Date().toISOString(),
};

const handlers: MatchChannelHandlers = {
  onMessage: (envelope) => {
    console.log('Nhận thông điệp:', envelope.type, envelope.payload);
  },
  onPresenceChange: (members) => {
    console.log('Danh sách đấu thủ trong phòng:', members);
  },
  onStatusChange: (status, detail) => {
    console.log('Trạng thái kênh:', status, detail);
  },
};

// 1. Tạo instance theo từng trận đấu (KHÔNG Singleton)
const matchChannel = createMatchChannel('match-uuid-hoac-MA6SO', self, handlers);

// 2. Kết nối và theo dõi presence
await matchChannel.connect();

// 3. Gửi thông điệp (tự bọc TransportEnvelope v=1, senderId, sentAt)
await matchChannel.send('move', { row: 7, col: 7 });

// 4. Lấy danh sách thành viên hiện diện (đã sắp xếp tăng dần theo joinedAt)
const members = matchChannel.getMembers();

// 5. Ngắt kết nối và dọn dẹp sạch sẽ tài nguyên khi kết thúc trận
await matchChannel.disconnect();
```

## 4. QUYẾT ĐỊNH THIẾT KẾ TRONG PHASE

| Quyết định                                          | Lý do lựa chọn                                                                                                                                 | Phương án đã loại bỏ & Rủi ro                                                            |
| :-------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------- |
| **KHÔNG dùng Singleton cho `matchChannel`**         | Mỗi ván đấu tạo 1 instance riêng biệt giúp cô lập 100% state giữa các trận, ngăn chặn rò rỉ bộ nhớ và sự kiện rác từ ván cũ.                   | _Dùng Singleton toàn app_: Gây dính coupling ván cũ, không thể chuyển phòng sạch sẽ.     |
| **Tái dùng Singleton `supabaseClient`**             | Tránh tạo instance Supabase thứ 2, tiết kiệm kết nối Auth và ngăn ngừa hiện tượng lệch phiên JWT giữa DB và Realtime.                          | _Tạo client thứ 2 trong transport_: Lãng phí tài nguyên, tốn 2 kết nối auth đồng thời.   |
| **Bỏ qua an toàn khi nhận envelope lạ (`v !== 1`)** | Kênh Realtime Broadcast là môi trường mở. Client có thể nhận gói tin rác/phiên bản cũ. Ghi `console.warn` và bỏ qua giúp app không bị crash.   | _Throw Error khi nhận gói tin lạ_: Khiến UI bị sập khi có người chơi dùng client bản cũ. |
| **Khống chế `eventsPerSecond: 10`**                 | Game đối kháng theo lượt chỉ phát sinh 0.2 - 1 msg/s. Ngưỡng 10 msg/s vừa mượt mà vừa ngăn ngừa spam/infinite loop cạn kiệt 2M messages/tháng. | _Không giới hạn_: Nguy cơ bị cạn kiệt quota Free Tier chỉ sau một lỗi loop vô tận.       |
| **KHÔNG tự động reconnect trong lõi**               | Tầng Transport báo cáo trạng thái trung thực ('error', 'closed'). Quyết định chính sách reconnect thuộc về tầng quản lý phiên/UI (P3.5).       | _Lõi tự reconnect ngầm_: Gây khó kiểm soát vòng đời và tạo kết nối ma ngoài ý muốn.      |
