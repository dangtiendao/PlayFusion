## 3. HỢP ĐỒNG CÔNG KHAI (PUBLIC CONTRACTS)

### A. Phong Bì Thông Điệp (`TransportEnvelope<T>`)

Mọi thông điệp trao đổi qua Broadcast bắt buộc tuân theo phong bì Version 1:

```typescript
export interface TransportEnvelope<T = unknown> {
  readonly v: 1; // Cố định = 1
  readonly type: string; // Loại thông điệp ('move', 'sync_state', 'ping'...)
  readonly senderId: string; // UUID người gửi
  readonly sentAt: string; // ISO 8601 UTC timestamp
  readonly payload: T; // Dữ liệu gói tin
}
```

### B. Quy Ước Kênh & Validate Mã Phòng

- **Quy ước tên kênh Realtime**: Luôn có định dạng `match:{matchId}` (Ví dụ: `match:ROOM01`, `match:7b8e5c12-32a1-4091-86bf-6f5df8b8fa21`).
- **Validate `matchId`**: Bắt buộc là UUID chuẩn hoặc mã phòng 6 ký tự `^[A-Z0-9]{6}$`.

### C. Chữ Ký React Hook `useMatchChannel` (Dùng Cho Màn Hình Trận Đấu P3.3)

```typescript
import {
  useMatchChannel,
  type UseMatchChannelOptions,
  type UseMatchChannelResult,
} from '@/transport';

export interface UseMatchChannelOptions {
  readonly matchId: string | null; // null -> tắt kết nối (trạng thái idle)
  readonly self: PresenceMember | null; // Thông tin người chơi hiện tại
  readonly onMessage: (env: TransportEnvelope) => void; // Callback nhận thông điệp
  readonly enabled?: boolean; // Mặc định true; false -> không kết nối
}

export interface UseMatchChannelResult {
  readonly status: ChannelStatus; // 'idle' | 'connecting' | 'connected' | 'error' | 'closed'
  readonly members: readonly PresenceMember[]; // Danh sách người trong phòng (sort theo joinedAt)
  readonly send: (type: string, payload: unknown) => Promise<void>; // Gửi Broadcast
  readonly reconnect: () => Promise<void>; // Kết nối lại thủ công
}
```

**Ví dụ sử dụng ngắn trong màn hình ván đấu online**:

```typescript
const { status, members, send } = useMatchChannel({
  matchId: activeRoomCode,
  self: { userId: user.id, displayName: user.displayName, joinedAt: joinedAtRef.current },
  onMessage: (envelope) => {
    if (envelope.type === 'game_state_update') applyServerState(envelope.payload);
  },
  enabled: isPlayingOnline, // Bật/tắt linh hoạt theo màn hình
});
```

### D. Selectors Tiện Ích Từ `transportStore` (UI Đọc Trực Tiếp)

import {

## 4. QUYẾT ĐỊNH THIẾT KẾ TRONG PHASE

| Quyết định                                                       | Lý do lựa chọn                                                                                                                                                                                  | Phương án đã loại bỏ & Rủi ro                                                                                |
| :--------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------- |
| **Realtime Broadcast/Presence là "Dumb Pipe"**                   | Broadcast không qua RLS bảng. Transport chỉ đóng vai trò ống truyền; mọi hành động có giá trị pháp lý (nước đi, xác định thắng thua) **bắt buộc thẩm định qua Edge Function Trọng Tài (P3.2)**. | _Tin tưởng kết quả gửi trực tiếp từ client_: Nguy cơ bị hack client gửi nước đi sai luật hoặc tự nhận thắng. |
| **Store in-memory, KHÔNG lưu Channel instance**                  | Store chỉ phản chiếu dữ liệu phẳng (`status`, `members`, `lastError`). Vòng đời channel do hook sở hữu.                                                                                         | _Lưu channel trong store_: Gây rò rỉ kết nối treo vĩnh viễn khi React hot-reload/refresh.                    |
| **Chống Race Condition kép (`connectionIdRef` + `isCancelled`)** | Nếu component bị unmount trong khi `channel.connect()` đang pending bất đồng bộ, kết nối sẽ tự động bị hủy bỏ ngay khi vừa resolve trong khối `.finally()`.                                     | _Chỉ dùng cleanup thông thường_: Kết nối mồ côi (orphan connection) tiếp tục sống ngầm sau khi unmount.      |
| **Giữ callback `onMessage` qua Ref**                             | Tránh việc component cha re-render và truyền inline arrow function làm re-trigger `useEffect` gây disconnect/reconnect liên tục.                                                                | _Đưa `onMessage` vào dependency array_: Tốn tài nguyên và ngắt quãng trận đấu sau mỗi lần re-render.         |
| **Chính sách Mobile `visibilitychange`**                         | Game đối kháng theo lượt (Caro), người chơi chuyển app trả lời tin nhắn trong vài giây là bình thường. Supabase WebSocket tự có timeout; client giữ kết nối để không đứt đoạn trải nghiệm.      | _Ngắt ngay khi hidden_: Người chơi bị văng khỏi phòng mỗi khi chuyển app đọc thông báo.                      |
| **Khống chế `eventsPerSecond: 10`**                              | Game lượt chỉ phát sinh 0.2 - 1 msg/s. Ngưỡng 10 msg/s bảo vệ hạn mức 2M messages/tháng của Free Tier khỏi nguy cơ loop vô tận.                                                                 | _Không giới hạn_: Nguy cơ cạn kiệt quota chỉ sau một lỗi gửi tin lặp.                                        |
